# Architecture rules

Prefix: ARC.

## Who owns what

- **ARC1:** `entrypoint.sh` is the image's whole program (`/usr/local/bin/mql-compiler` in the image). It owns collecting sources, the toolchain setup, the include root and the compile loop. Logic that has to run inside the container lives there and nowhere else.
- **ARC2:** `wrapper.sh` is the host command and stays a thin `docker run`: it resolves paths and `-I` directories, picks the mounts, sets the working directory, the UID, `--init`, the seccomp profile, the cache volume and the forwarded variables, then `exec`s Docker. It never parses MQL, compiles or touches the cache. It knows the output format only to report its own errors the same way, and it cannot rely on `jq` (it runs on the user's machine).
- **ARC3:** `install.sh` only installs, upgrades and removes the command. It rewrites the `readonly PINNED_IMAGE=` and `readonly SECCOMP_PROFILE=` lines of `wrapper.sh` and refuses to overwrite a file without the `mql-compiler-managed-command` marker line. Keep those lines and that marker exactly as they are; `install.sh` matches them.
- **ARC4:** There is no config file and no config directory. Settings are environment variables: `MQL_COMPILER_IMAGE`, `MQL_COMPILER_VOLUME` and `MQL_COMPILER_SECCOMP` (wrapper), and `MQL_COMPILER_MT4_URL`, `MQL_COMPILER_MT5_URL` and `MQL_COMPILER_INSTALL_TIMEOUT` (forwarded by `FORWARDED_VARS` in the wrapper, read by the entrypoint). `MQL_COMPILER_ENV=dev` is the installer's switch for installing from a checkout. A new variable the image reads is added to `FORWARDED_VARS` and documented in the environment table in `docs/installation.md`.

## A run

- **ARC5:** One invocation is one container, and files compile one at a time in it. Arguments keep their order, each directory's files are sorted, and a file named twice compiles once (`collect_sources` and the `awk` dedupe in `main`). Do not compile in parallel: the files share one Wine prefix and one wineserver. For the same reason a whole run, setup included, holds `flock` on `/cache/uid-<UID>/.run.lock` (`acquire_run_lock`), so a second run waits instead of sharing the prefix and the log. `--watch` releases it while waiting for changes and takes it again for every pass.
- **ARC6:** The extension alone picks the compiler: `.mq4` goes to MT4's `metaeditor.exe`, `.mq5` to MT5's `metaeditor64.exe` (`compile_one`). The nearest enclosing directory named `MQL4` (for `.mq4`) or `MQL5` (for `.mq5`), matched case-insensitively, decides only which user `Include` and `#resource` tree the file sees (`user_mql_root`).
- **ARC7:** Every path in the container equals the host path. The wrapper passes `realpath`ed arguments and mounts, at the same path, the directory each one includes from by the same rule as ARC6 (`include_folders`: the nearest `MQL4` above a `.mq4`, `MQL5` above a `.mq5`, either above a directory), or the directory itself or the file's directory. It drops mounts nested in another, refuses to mount `/`, and runs with `-w` set to the physical current directory. Mounting less than the `MQL4`/`MQL5` directory hides the user's `Include`.
- **ARC8:** Nothing is written into the user's directories except the `.ex4`/`.ex5` next to each source, and nothing into the toolchain after setup. The include root for a compile is built under the run's staging directory in `/tmp` (`build_merged_root`): `cp -rs` links of the terminal's standard `Include`, the user's `Include` linked over it with `--remove-destination` so the user's file wins, and links to the user's other top-level directories. It is built once per platform and user directory per run, and `cleanup` removes the staging directory.
- **ARC9:** MetaEditor's `/inc:` takes one directory (the `MQL4`/`MQL5` level, not `Include`), and neither `/inc:` nor `/compile:` works with a path containing spaces (MetaEditor writes no result). Any include root handed to it lives under the staging directory, never in a terminal directory (a mounted one often has spaces), and a source path with whitespace is compiled through a link in the staging directory to its `MQL4`/`MQL5` directory or its own directory (`stage_source`).
- **ARC10:** MetaEditor's exit code means nothing (1 usually means success). The verdict is the last `Result:` line of its UTF-16 log, read by `read_log`. A missing `Result:` line is a failure. The `.ex4`/`.ex5` is deleted before each compile (`compile_one`), because MetaEditor only deletes it on compile errors and cannot delete a read-only one.
- **ARC11:** `read_log` maps every path in MetaEditor's log back to a real one: `Z:\` to `/`, anything under the staging directory to the file behind its link (`real_path`, with a missing include shown under the user's directory), and the current directory dropped where a path starts. It uses Bash string replacement, not `sed`, so any character in a path is safe. Logs go to stderr as JSON lines, and both streams are copied to `/cache/uid-<UID>/logs/last-run.log`, with `finish` waiting for the `tee` processes before the container exits.
- **ARC17:** stdout is the output contract. By default it is JSON Lines: a `file` record per source (`source`, `platform`, `status`, `output`, `errors`, `warnings`, `messages`, and `log` only without a result), a `summary` after each pass, an `error` record when the run cannot start, a `version` record from `--version`, `--setup` and `--update`. `--text` and `--format gnu` are renderings of the same `file` record (`print_file_result`). Exit `0` all compiled, `1` at least one failed, `2` usage or setup failure, `130` a stopped `--watch` (`EXIT_*` constants). Adding a field is compatible; renaming or removing one, or changing an exit code, is a breaking change that needs a minor version bump and a CHANGELOG line saying so. The "What comes out" section in `docs/usage.md`, SKILL.md and `action/run.sh` all read this contract; change them together.
- **ARC18:** The include root layers, in order: the standard `Include`, each `-I` directory in the order given, the user's `Include`. A later layer wins on a clash, so the user's own headers always win.
- **ARC19:** `--update` moves the Wine prefix to `wine.previous`, installs fresh, and moves it back if the install fails, under the run lock. Never delete the working toolchain before a replacement works.
- **ARC21:** `--mt4-terminal DIR` / `--mt5-terminal DIR` point a platform at a portable terminal: `find_metaeditor` returns that directory's MetaEditor and `stdlib_root` its `MQL4`/`MQL5` directory (matched case-insensitively), so the include root, `--version` and messages all follow it. `terminal_folder` refuses, with exit 2, a directory without the MetaEditor or without the unpacked standard-library marker. `install_toolchain` skips such a platform entirely (no download, no install, no unpack), and a compile installs only the platforms its sources need (`needed_platforms`; `--watch` takes both). The wrapper mounts the directory read-only (SEC6), and a read-write source directory inside it is mounted on top; the cached toolchain is never changed by a run with these options.
- **ARC20:** The GitHub Action (`action.yml`) runs `wrapper.sh` from the same ref, with the image matching that ref, and reads only the JSON contract (ARC17). `make test` runs `action/run.sh` with GitHub's files faked, and CI also runs the action itself (`uses: ./` in the `action` job of `pipeline.yml`) against an image that job builds from the same commit.

## Toolchain and cache

- **ARC12:** No MetaQuotes software goes into the image or the repository. The first run downloads the installers, verifies them (SEC1), installs them with `/auto`, waits with `wineserver -w`, and starts each terminal once with `/portable` until it unpacks its standard library (`unpack_stdlib`, markers `Include/Trade/Trade.mqh` and `Include/stdlib.mqh`). `make_portable` then moves the installed directory out of `Program Files` to `drive_c/terminals/mt4` or `mt5`, so a cached terminal is a portable directory like a mounted one and every compile resolves through `terminal_dir`. Inside the prefix, so `--update`'s rollback (ARC19) moves it along. A cache with an install still under `Program Files` (from before v0.5.0) is moved the same way on its next run, with no download; `find_installed_metaeditor` finds it. The installer's registry and Start menu entries stay in the prefix unused.
- **ARC13:** Xvfb stays up for the whole run. The installers hand off to a child process that dies with the display.
- **ARC14:** The cache is `/cache/uid-<UID>/` with `home`, `wine`, `installers` and `logs`, one directory per UID in one volume, because Wine refuses a prefix owned by another UID. `/cache` is mode 1777 in the image. `main` refuses a `uid-<UID>` directory owned by another UID before touching it. The run lock (ARC5) also keeps parallel first runs from installing twice.
- **ARC15:** `wineserver -p` needs an existing prefix, so `keep_wineserver` runs after `ensure_toolchain`.
- **ARC16:** The image is amd64 only. MT4's MetaEditor is 32-bit and needs Wine's i386 half (`wine-stable-i386:i386`).
